## Zero-LLM evidence

`zero-llm.spec.ts` writes `zero-llm.json` after its four assertions. The artifact records the static scan of Host and Client source files (no forbidden module import, `ctx.llm`/`ctx.tools` access, auxiliary purpose literal or `SessionEventMap` contribution) and the seven service journals for six runtime scenarios: store plus Remote snapshot, scheduler dispatch, recovery reconciliation, pressure measurement and pricing, handoff body rendering and delivery, and run supervision. Every journal value must be `0`; a non-zero value fails the spec.

## Invariants asserted across the matrix

- Reconciliation uses the operation source (`operationId` + `runId` +
  `generation` + `attempt`), never a bare `MessageId`.
- `uncertain` and unverifiable cases become `needs-attention`; nothing is
  replayed and no second Session is created.
- Every durable state transition is a revision/phase CAS; a crashed write is
  detected by re-reading durable state, not by replaying the effect.
- The scheduler is only open after a successful reconciliation pass.
